# Team Roles and Two-Week Plan

## Suggested roles (adapt to team size)
- Design lead: brand guidelines, wireframes, layout consistency.
- Development lead: page structure, CSS, JavaScript, responsive behavior.
- Research and content lead: interviews, fact-checking, writing, citations.
- Media and QA lead: photography/graphics permissions, asset organization, browser and accessibility testing.

Every member should understand the complete website, not only their assigned section.

## Two-week schedule
| Day | Focus | Evidence of progress |
|---|---|---|
| 1 | Understand event requirements; choose community focus | Event checklist and research plan |
| 2 | Interview/research; select stories | Verified notes, source list, permissions plan |
| 3 | Brand direction and page wireframes | Approved brand sheet and page sketches |
| 4 | Learn project structure; customize design tokens | Consistent header, typography, colors |
| 5–7 | Build pages and reusable components | Working landing page and subpages |
| 8 | Add original media, quotes, and evidence | Asset log and complete draft content |
| 9 | Responsive and accessibility review | Mobile/tablet/desktop fixes |
| 10 | Browser, link, and offline testing | QA checklist |
| 11 | Works Cited, releases, AI documentation | Complete documentation package |
| 12 | Polish and validate final website | Submission-ready local folder |
| 13 | Presentation scripting and rehearsal | Timed five-minute presentation |
| 14 | Final offline test and contingency rehearsal | Backup copy and final sign-off |

## Five-minute presentation outline
- 0:00–0:30 — Introduce the community focus and purpose.
- 0:30–1:15 — Explain audience, brand, and design choices.
- 1:15–3:30 — Demonstrate key pages, navigation, content, and media.
- 3:30–4:30 — Explain technical implementation, accessibility, and compatibility.
- 4:30–5:00 — Summarize team roles and impact.

Adjust the script to the current official presentation rules and rehearse with a timer.
